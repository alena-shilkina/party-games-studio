# Party Games Studio

Приложение переехало с хостинга redcheeksgirl.com на Cloudflare Worker.
Больше не нужно заливать HTML руками: правим исходники → одна команда → уже на сайте.

**Адрес:** https://party-games-studio.alena-shilkina.workers.dev
Вход по паролю, пароль хранится на стороне Cloudflare (секрет `APP_PASSWORD`).

---

## Как выложить изменения

```
npm run deploy
```

Собирает страницу и отправляет её в Cloudflare. Занимает секунд десять.

Посмотреть изменения локально, не трогая прод:

```
npm run dev
```

Прогнать проверки, не выкладывая:

```
npm run verify
```

`npm run deploy` запускает их сам и не выложит сборку, если что-то не сошлось.

## Ключи и пароли

Всё хранится секретами на стороне Cloudflare. В браузер они не попадают: приложение
обращается к `/api/…`, а ключ подставляет Worker уже на сервере.

Задать (команда спросит значение, на диск оно не пишется):

```
npx wrangler secret put APP_PASSWORD        # пароль на вход в приложение
npx wrangler secret put ANTHROPIC_API_KEY   # Claude
npx wrangler secret put RUNWARE_API_KEY     # Runware
npx wrangler secret put PEXELS_API_KEY      # Pexels
npx wrangler secret put WP_USER             # логин WordPress
npx wrangler secret put WP_PASS             # пароль приложения WordPress
```

Посмотреть, что уже задано (значения не показываются, только имена):

```
npx wrangler secret list
```

Удалить:

```
npx wrangler secret delete PEXELS_API_KEY
```

Поменять — просто задать заново той же командой `put`.

Секреты применяются сразу, передеплоивать не нужно. Только `APP_PASSWORD` после смены
разлогинивает — надо зайти заново.

### Пока секрет не задан

Приложение продолжает работать по-старому: Worker возьмёт ключ из поля в Настройках.
Как только секрет появился, соответствующее поле в Настройках гаснет с подписью
«хранится на сервере» — заполнять его больше не нужно.

При первом запуске после этого приложение стирает из хранилища браузера всё, что
теперь лежит на сервере: старые ключи из полей и логин WordPress в карточках сайтов.
В карточке остаются только название, адрес и категория.

Что уже лежит на сервере, приложение узнаёт при запуске через `/api/keys`.

рассчитан на то, что всё лежит в одном файле подряд, как было раньше.

## Про WordPress

Приложение публикует посты через `wp-proxy.php` и `wp-media-proxy.php`, которые лежат
на самом сайте. Раньше браузер обращался к ним напрямую — теперь это невозможно,
приложение и сайт на разных доменах, и браузер такие запросы блокирует.

Поэтому запросы идут через Worker: `/api/wp?site=…&file=wp-proxy.php`. Worker обращается
к сайту сам, со своей стороны этого ограничения нет. В PHP на сайте ничего менять
не пришлось.

Проксировать разрешено только на домены из `ALLOWED_WP_HOSTS` в `wrangler.toml`
и только в эти два файла — чтобы через приложение нельзя было дёргать что попало.
Появится второй сайт — добавь его домен туда.

## Пины выключены

Генерация четырёх пинов и блок «Save These for Later» в конце статьи отключены —
пины будет делать pin-scheduler. Код не удалён, он рабочий.

Вернуть: в `src/app/js/12-images-pins.js` поставить

```
const PINS_ENABLED=true;
```

и выложить. Обратно вернётся всё сразу: блок в сайдбаре, поле с заголовками пинов
в строке пакета, раздел пинов в превью и блок в конце опубликованной статьи.

Пока выключатель снят, приложение не делает ни запрос к Claude за текстами пинов,
ни четыре генерации картинок — это заметная экономия на каждой статье.

## Правила текста

`src/app/js/07a-humanizer.js` — свод из скилла blog-copy-humanizer, переложенный
в инструкцию для модели. Он подставляется во все четыре режима генерации статьи
сразу после блока «тон голоса» и намеренно перебивает всё, что сказано о стиле выше:
запрет на выдуманные факты, список запрещённых слов и оборотов, ноль длинных тире,
ноль эмодзи, прямые кавычки, требования к заголовку и мета-описанию.

Отдельно там же короткий свод для пинов — там модель пишет только CTA в два-четыре слова.

Список форматов, которые скилл разрешает и которые НЕ надо «чинить», тоже внутри:
жирный на названиях игр, Title Case в подзаголовках, нумерованная структура листикла.

Правишь блок — правишь один файл, он попадёт во все режимы сразу.

## Что проверяет verify

Раньше здесь была побайтовая сверка с версией, скачанной с сайта. Она годилась, пока
переезд был чистым переносом. Теперь приложение развивается, и такая сверка мешала бы.
Вместо неё проверяется то, что должно быть верно всегда:

- все модули на месте и непустые, собранный JS разбирается без синтаксических ошибок;
- не вернулось наследие старого хостинга (шрифты `/cf-fonts/`, анти-бот скрипт);
- ключи не уходят в браузер: нет прямых вызовов Anthropic, Runware, Pexels и WordPress;
- блок правил текста подставлен во все четыре режима и в пины;
- каждая функция из `onclick` в разметке действительно существует;
- до очереди ревью, пакета и настроек можно добраться из интерфейса.

Последняя проверка появилась не зря: панель банка игр какое-то время была недоступна —
функция существовала, а кнопки, которая её вызывает, не было нигде. Сам банк с тех пор
удалён (типы игр задаются через ТЗ), но проверка осталась и сторожит остальные панели.

`original-downloaded.html` остаётся в проекте как исходная версия для истории.

## Мелочь про локальный запуск

`npm run dev` берёт пароль из файла `.dev.vars` (там стоит `local-test-only`).
Это только для локальной проверки, на боевой адрес никак не влияет.
